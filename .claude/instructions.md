# VoxelWorlds: instructions

> State as of 2026-11-02 (code review CR5). Terms: `Documentation/GLOSSARY.md`.

VoxelWorlds is the project's voxel terrain engine for Unreal Engine 5.8: generation (noise, world modes, biomes, caves,
ore, water, voxel trees), three meshers (cubic, Marching Cubes, Dual Contouring), streaming with LOD, collision and far
compression, a renderer on `FLocalVertexFactory`, the far field to the horizon, an edit layer, scatter, a map,
surface navigation and runtime PCG. It depends on no other project plugin, and none of the game plugins' types appear in it.

## Modules (`Source/`)

| Module | What it holds |
|--------|---------------|
| `VoxelCore` | Voxel and chunk types, the world configuration and `UVoxelWorldsSettings`, material and biome registries, the edit manager, the sea surface and the water levels, cube-sphere and render-region math; no dependency on another voxel module |
| `VoxelGeneration` | CPU and GPU generation, the noise (`FVoxelNoise`), world modes behind `IVoxelWorldMode` and `FVoxelWorldModeFactory`, surface queries, conditioning zones and lines, the tree injector |
| `VoxelLOD` | `IVoxelLODStrategy` and `FDistanceBandLODStrategy`: the voxel window, bands, horizons, the cut-over |
| `VoxelMeshing` | `IVoxelMesher`: the CPU cubic, Marching Cubes and Dual Contouring meshers (chunk meshes and seams), the water mesher |
| `VoxelRendering` | `IVoxelMeshRenderer` and `FVoxelMeshRenderer`: a `UVoxelRegionComponent` per render region, `FVoxelSceneProxy`, the crossfades |
| `VoxelStreaming` | `UVoxelChunkManager` and its owners (seams, snapshots, collision, far compression, water, far field, oceans, viewer policy), `AVoxelWorldActor`, the bench, the plugin's console commands (`Private/Diagnostics/`) |
| `VoxelScatter` | `UVoxelScatterManager` (extraction, placement) and `UVoxelScatterRenderer` (HISMs per region) |
| `VoxelMap` | `UVoxelMapSubsystem`: map and minimap tiles, the globe, the edit overlay |
| `VoxelNavigation` | `UVoxelSurfaceNavigationSubsystem` and `FVoxelSurfacePathfinder`: A* over the surface without a navmesh |
| `VoxelPCG` | The PCG surface sampler and biome dispatcher; the only module that depends on the PCG plugin |
| `VoxelWorldsEditor` | Editor only: the field preview panel and actor (`AVoxelFieldPreviewActor`) |

## Rules that hold

- **Generation on the GPU, with a CPU twin.** Chunk voxels are generated by compute shaders
  (`Shaders/Private/GenerateVoxelDensity.usf`, `VoxelPostPasses.usf`) and read back; the CPU generator does the same
  work (`-VoxelForceCPU`, `voxel.Stream.GPUGeneration 0`). A generation change lands on both sides, and the
  `VoxelWorlds.Generation.GPUvsCPU*Parity` tests must pass in the editor. A change to what a world generates bumps
  `FVoxelWorldModeFactory::GenerationVersion` (heightmaps, 3) or `PlanetGenerationVersion` (planets, 6), which refuses
  older saves.
- **Meshing on the CPU, with seam ownership.** Every mesher meshes a chunk's interior from its own voxels only; each
  chunk boundary (face, edge, corner) belongs to one seam job that reads both sides (`FVoxelSeamRegistry`). A chunk
  never waits for, or re-meshes on, a neighbour; an edit re-meshes the chunks it changed and restales their seams.
  Do not add a mesher path that reads a neighbour's voxels into a chunk mesh.
- **Voxel reads go through snapshots.** A reader off the game thread takes a chunk's edit-merged voxels as an immutable
  snapshot (`UVoxelChunkManager::GetVoxelSnapshot`, taken on the game thread; shared copy-on-write with the resident
  array, or decoded by a worker from far compression), never a raw pointer to a descriptor's array, and nothing expands
  a compressed chunk on the game thread.
- **World modes through `IVoxelWorldMode`.** Build modes and their params only through `FVoxelWorldModeFactory`; game code
  reaches bounds, local up, altitude and the surface coordinate through the chunk manager (`Voxel|World` functions).
  Never assume +Z is up or compare a Z with `WaterLevel`: water is read through the world's water levels
  (`UVoxelChunkManager::GetWaterLevels`: `Sample` at a position, `GetRange` over the bounds a level is copied for,
  `GetSea` for geometry drawn at the sea), and `FVoxelWaterLevels::FromConfig` is the only reader of the
  configuration's `WaterLevel` and `WaterRadius` (WATER_SYSTEM.md, "The water levels").
- **The surface ladder.** `UVoxelChunkManager::QuerySurfacePoint` with `EVoxelSurfaceLayer`: `Natural` (the world
  mode's), `Generated` (conditioning lines and zones applied, block tops on a cubic world; `GetGeneratedSurfacePoint`) or `EditMerged`
  (the loaded voxels; `QueryEditMergedSurfacePoint`). Pick the rung you mean; `GetTerrainHeightAt` is a heightmap's
  natural height and degrades on a planet.
- **Precision.** Planets are precise to about 1,000 km and heightmaps to the double range of a position: never hold a
  value of size R in float (altitudes in double on the CPU, the chunk's frame on the GPU, `PlanetFrame.ush`); primitives
  sit at their render region's origin (`FVoxelRenderRegions`) and store float offsets from it.
- **Mode-generic names.** A type, function or cvar that works in every mode carries no mode in its name (`FVoxelFarField`,
  `FVoxelNoise`, `VoxelCutoverAltitude`); a reflected rename gets a `[CoreRedirects]` entry in `Config/DefaultVoxelWorlds.ini`.
- **Console names.** Every command and cvar the plugin registers is `voxel.<System>.<Name>` in the group of the system
  that reads it (`voxel.World`, `Stream`, `Mesh`, `Seam`, `Snapshot`, `FarCompression`, `Collision`, `Edit`, `Water`,
  `Scatter`, `Render`, `Material`, `Map`, `Nav`, `Bench`, ...). The plugin owns its diagnostics (stats, audits,
  traces); the game module's `vox.*` commands puppeteer the pawn and may alias a `voxel.*` command, never the reverse.
  A new cvar gets an entry in the console guide. Tuning values belong on the configuration or `UVoxelWorldsSettings`;
  a cvar overrides them.
- **Independent plugin.** VoxelWorlds includes no game plugin (VoxelCharacterPlugin, VoxelWorldPOI, ...); they reach
  it through the chunk manager, `IVoxelEditValidator` and delegates.
- **Blueprint exposure** on public API (`UFUNCTION`), only Blueprint types on Blueprint properties (`uint8`, `int32`,
  `int64`; no other unsigned or narrow integers), `/** */` comments on public functions;
  `Documentation/Guides/CODING_STANDARDS.md` has the rest.

## Tests and the in-editor gate

Each module keeps its automation tests in `Tests/` (`VoxelWorlds.*`). Headless runs (`-nullrhi`) skip, not fail, every
test that needs a real RHI: the GPU parity tests, the GPU noise test and the renderer tests that need a scene proxy
(`Rendering.Crossfade.SwapReachesProxy`, `Streaming.EditReachesProxy.*`). A change to generation, meshing or rendering
is gated in the editor (the `unreal-mcp` automation toolset, with `vox.Tests.GCEveryWorlds` on), not by a headless pass
alone. `Documentation/Guides/TESTING_STRATEGY.md` has the suites, the commands and the bench protocol.

## Findings

A bug or gap found while working and not fixed in the same change gets the next G-number in the project's findings
register, `Documentation/FINDINGS.md` (one row: what, where, how found, what a fix would be). When fixed, the result
goes into the Features doc of the system, with the ID after the fact.
